# PrintDrop
### A Web-Based Document Submission and Print Queue Management Application

**Project Type:** Full-Stack Web Development  
**Development Approach:** AI-Assisted Development  
**Repository:** [GitHub - PrintDrop](https://github.com/Adeen0504/PrintDrop)  
**Deployment:** Render

---

## 1. Project Overview

PrintDrop is a web-based application designed to simplify document submission and print queue management for local Xerox and printing shops.

The idea originated from observing a common problem in traditional Xerox shops. When a new customer arrives, shop owners often need to manually save the customer's phone number, receive documents through messaging applications, and manage multiple printing requests.

This process can become repetitive and inconvenient, especially when handling multiple customers.

PrintDrop was developed to address this problem by creating a centralized platform where customers can submit documents and printing requirements, while shop owners can manage incoming requests through a dedicated interface.

The project was developed using an AI-assisted approach, with a strong emphasis on problem identification, requirement planning, logical thinking, testing, and implementation review.

## 2. Problem Identification

The initial idea came from identifying an inefficiency in the traditional Xerox shop workflow.

Whenever a new customer visits a shop, the owner may need to:

- Save the customer's phone number.
- Receive documents through messaging applications.
- Understand the customer's printing requirements.
- Keep track of multiple incoming requests.
- Manually manage pending and completed printing jobs.

Although these steps are individually simple, repeating them for every customer creates unnecessary work.

The objective was to develop a web application that would reduce these repetitive interactions and organize the entire document submission process.

## 3. Requirement Planning and Feature Design

Before writing any code, I created a detailed text document containing the application's requirements.

Rather than simply describing the idea, I broke the application down into individual features and explained how each feature should function.

The planning document included:

- The problem the application was intended to solve.
- The features required to address that problem.
- How individual features should behave.
- How different parts of the application should interact.
- How the user interface should look.
- What the expected output of different operations should be.

I also organized the requirements into separate feature blocks, explaining the expected functionality of each component.

This helped establish a clear development direction before implementation began.

## 4. AI-Assisted Development Process

Once the requirements were finalized, I provided the complete planning document to an AI tool and used it to generate the application's code.

My development process followed these stages:

### Step 1: Defining the Requirements

I first identified the real-world problem and documented the features needed to solve it.

I focused on explaining the expected functionality rather than starting with programming languages or code.

### Step 2: AI-Assisted Code Generation

I provided the requirements document to AI and used it to generate the application.

The generated implementation was based on the features, functionality, and expected outputs I had defined.

### Step 3: Running and Testing the Application

After receiving the generated code, I ran the application and tested whether the implemented features behaved as expected.

I compared the actual output with the requirements I had originally documented.

### Step 4: Logical Debugging and Problem Identification

When an error occurred or a feature did not behave as expected, I first tried to understand the problem from a logical perspective rather than immediately focusing on the code.

I examined what the application was supposed to do, what it was actually doing, and where the behaviour differed from the expected result.

Once I understood the issue, I explained the problem to AI and asked it to identify and implement a solution.

### Step 5: Refinement and Validation

After applying the suggested corrections, I ran the application again to verify whether the issue had been resolved.

This process was repeated whenever the implementation did not match the original requirements.

### Step 6: GitHub and Deployment

After completing the development and testing process, I pushed the project to GitHub for version control and deployed the application using Render.

## 5. Key Features

PrintDrop was designed around two primary user experiences.

### Customer Interface

- Google authentication.
- Document uploading.
- Printing preference selection.
- Print request submission.
- Queue position information.
- Previous submission history.

### Shop Owner Interface

- Dedicated administrative dashboard.
- Centralized view of incoming print requests.
- Access to submitted documents.
- Print queue management.
- Job status updates.
- Overview of pending and completed requests.

These features were designed to reduce repetitive communication and provide a more organized printing workflow.

## 6. Challenges and Problem-Solving

One of the main challenges was ensuring that the generated application matched the original requirements.

Since the application was developed using AI-generated code, the implementation did not always behave exactly as expected.

Instead of blindly accepting generated solutions, I followed a problem-solving approach:

1. Identify the difference between expected and actual behaviour.
2. Understand the issue logically.
3. Explain the problem clearly to AI.
4. Review the proposed correction.
5. Run the application again to validate the solution.

This approach helped me focus on understanding application behaviour and solving problems rather than simply generating code.
